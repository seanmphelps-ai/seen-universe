# SEEN — Phase 1 Environmental Field Prepass

Phase 1 begins with environment, not questionnaire intake.

The first SEEN runtime pass builds the place-field before birth date, temporal narrowing, chart interpretation, wound narration, portal routing, or Oracle rendering.

The user does not begin by answering personal history questions.

The user provides location data first.

## Front-Door Location Data

The first shell asks only for place-field coordinates needed to build the environmental pressure map:

1. Birthplace
2. Early childhood locations, if known
3. Adolescent locations, if known
4. Major lived locations, if relevant
5. Current location
6. Relationship, rupture, replay, or event-relevant location, when applicable

Birth date enters after the environmental prepass exists.

The date gives structure.

The environment shows what cooked the structure.

## Environmental Marker Rule

The Generator must derive environmental markers before reading the natal chart.

At minimum, the environmental prepass evaluates:

- biome pressure
- abiotic pressure
- GeoPresence
- climate field
- altitude field
- terrain field
- light-cycle pressure
- density or isolation pressure
- seasonal pressure
- water / desert / mountain / coastal / forest / plains field
- resource stability pressure
- cultural and environmental pace
- sensory load
- mobility and access pressure
- origin-current-location friction
- adolescent-place imprint
- current-terrain regulation or destabilization

These are not decorative context.

They are the first pressure container.

## Place-Phase Separation

The Generator must preserve location phases separately before synthesis:

1. Birthplace imprint
2. Early childhood field
3. Adolescent field
4. Major lived-location field
5. Current-location field
6. Event-location field, when applicable

Each phase may amplify, suppress, distort, stabilize, or reroute later signals.

Do not flatten all locations into a single generic place summary.

## Pre-Date Wound-Trigger Map

Before birth date is interpreted, the Generator creates an environmental wound-trigger map.

This map identifies which wound fields may be activated by place pressure, including:

- abandonment pressure
- rejection sensitivity
- shame exposure
- control response
- invisibility pressure
- responsibility distortion
- emotional suppression
- relational testing
- power-struggle pressure
- safety scanning
- scarcity response
- isolation adaptation
- overstimulation adaptation
- displacement pressure
- belonging pressure

These are candidate pressure fields.

They do not become user-facing claims until later convergence supports them.

## No Questionnaire Rule

There is no required intake questionnaire before the first read.

The system must not ask childhood, family, trauma, relationship, or self-description questions before the initial environmental prepass and first Generator scan.

Lived experience may be added later as optional refinement.

Post-reading lived experience can refine:

- confidence
- intensity
- routing
- expression
- distortion
- suppression
- amplification
- section priority

It does not create the first read.

## Runtime Order

The Phase 1 runtime order is:

1. Collect location field
2. Derive environmental markers
3. Build environmental pressure profile
4. Build pre-date wound-trigger map
5. Store environmental field
6. Bring in birth date
7. Run chart and time-anchor calculations
8. Generate hidden time-rectification summaries
9. Compare summaries by wound, behavior, attachment, rupture, shadow, and regulation difference
10. Send structured payload to Oracle rendering

The chart is never read in a vacuum.

The same chart in different terrain may express differently.

## Silent Modifier Stack

The environmental prepass organizes derived place pressure into silent runtime stacks:

- silentAmplifiers
- silentSuppressors
- silentDistortionFactors
- silentStabilizers
- silentRerouteSignals

This allows the engine to separate:

- what intensifies
- what suppresses
- what distorts
- what stabilizes
- what reroutes downstream interpretation

## Oracle Boundary

The Oracle receives structured payload only after the Generator completes the environmental prepass, birth-date integration, temporal summary comparison, and convergence pass.

The user does not receive raw mechanics.

The user receives clear recognition, pattern visibility, and regulation guidance.

## Stable Repo-Level Lock

Phase 1 is an environmental field prepass before it is a natal interpretation system.

It identifies how birthplace, childhood terrain, adolescent terrain, lived locations, current terrain, biome, abiotic conditions, GeoPresence, and environmental pressure shape, cook, amplify, suppress, distort, stabilize, or reroute later chart expression.

Birth date must not be interpreted before the environmental field exists.

All outputs remain probabilistic.

No environmental marker becomes a major user-facing claim without convergence.
