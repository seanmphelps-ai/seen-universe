## MODULE
[MODULE / SYSTEM NAME]

Your first responsibility is to establish and lock the authoritative intelligence base for this module BEFORE implementing, interpreting, scoring, summarizing, or integrating anything into SEEN.

The objective is to identify the strongest defensible source stack for this specific system and preserve its methodology accurately.

## 1. IDENTIFY THE AUTHORITATIVE SOURCE STACK

Research the system and identify sources in this priority order:

1. Primary/original sources
   - Foundational texts
   - Original technical documentation
   - Original published methodology
   - Historical source material where applicable

2. Modern authoritative technical sources
   - Critical translations
   - Academic or scholarly editions
   - Recognized reference works
   - Established practitioners/scholars whose work documents the actual mechanics of the system

3. Calculation/data authority
   - Identify the authoritative computational source for every astronomical, calendrical, geographic, mathematical, or ephemeris-dependent value.
   - For astrology, evaluate Swiss Ephemeris / Astrodienst as the calculation authority where applicable.

4. Independent verification sources
   - Find at least two credible independent sources capable of checking the implementation or methodology.

## 2. SOURCE EVALUATION

For every candidate source, record:

- exact title
- author/organization
- publication/version/date
- URL, ISBN, DOI, repository, or other durable identifier
- source type
- which mechanics it supports
- whether it is primary, secondary, computational, or verification material
- evidence of authority
- known limitations
- disagreements with other authoritative sources

## 3. EXTRACT THE MECHANICS

Extract the system as explicit reproducible mechanics.

For every mechanic document:

SOURCE → INPUT → CALCULATION/RULE → OUTPUT → INTERPRETATION AUTHORITY

Every implemented rule must be traceable backward to its source.

## 4. SEPARATE FOUR LAYERS

Keep these separate:

### A. RAW DATA
Observable/input facts.

### B. CALCULATED MECHANICS
Values produced deterministically from the raw data.

### C. TRADITIONAL INTERPRETATION
Meanings explicitly supported by the locked source stack.

### D. SEEN DERIVED INTELLIGENCE
Any inference, convergence rule, scoring, recognition logic, or interpretation created specifically by SEEN.

## 5. VALIDATION

Before declaring the module source-locked:

- reproduce known reference examples where available
- compare calculated outputs against an independent authoritative implementation
- test boundary conditions
- document discrepancies
- identify version-sensitive calculations
- record assumptions
- record unresolved questions

Validate the underlying mechanics.

## 6. PROVENANCE

Every rule entering the runtime must retain provenance sufficient to answer:

- Where did this rule come from?
- Which edition/version was used?
- What exact mechanic does the source support?
- Is the result calculated, quoted/paraphrased tradition, or SEEN-derived?
- Can another engineer reproduce it independently?

## 7. SOURCE LOCK

When research is complete, produce:

### MODULE SOURCE MANIFEST
Canonical sources and their roles.

### MECHANICS MANIFEST
Every implemented mechanic and its source.

### CALCULATION AUTHORITY
The software/data/reference implementation used to verify deterministic calculations.

### VALIDATION MATRIX
Test cases and independent comparisons.

### DISAGREEMENT REGISTER
Conflicting traditions, translations, calculations, or interpretations.
