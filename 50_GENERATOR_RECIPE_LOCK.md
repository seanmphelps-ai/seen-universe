# 50_GENERATOR_RECIPE_LOCK

This file defines how SEEN cooks the ingredients before any chart, wound marker, portal, modality, Oracle response, or user-facing output is produced.

No output may jump directly from raw input to prose.

The Generator maps first.

The Oracle reveals progressively.

---

## 1. CORE RULE

The Generator does not answer in one pass.

Every significant output must move through recursive passes.

Each pass must preserve the previous pass and only add:

- depth
- clarity
- structure
- routing precision
- signal resolution

No pass may restart, replace, flatten, overwrite, or reinterpret the system from scratch.

Each phase output becomes the input for the next phase.

---

## 2. ROLE SEPARATION

The Generator calculates, scores, routes, extracts, ranks, and compiles.

The Oracle renders.

The Generator does not perform Oracle narration.

The Oracle does not calculate, score, infer, rank, or decide what is present.

The Oracle receives a structured payload only after the Generator has completed the recipe.

---

## 3. ENVIRONMENT-FIRST LAW

The first Generator pass is environmental.

Birth date must not be interpreted before the environmental field exists.

The Generator first builds the place-field from:

1. birthplace
2. early childhood locations, if known
3. adolescent locations, if known
4. major lived locations, if relevant
5. current location
6. relationship, rupture, replay, or event-relevant location, when applicable

The Generator derives:

- biome pressure
- abiotic pressure
- GeoPresence
- climate field
- altitude field
- terrain field
- light-cycle pressure
- density or isolation pressure
- seasonal pressure
- resource stability pressure
- cultural and environmental pace
- sensory load
- mobility and access pressure
- origin-current-location friction
- adolescent-place imprint
- current-terrain regulation or destabilization

This environmental field is stored before birth date enters interpretation.

The date gives structure.

The environment shows what cooked the structure.

---

## 4. FIXED GENERATOR ORDER

The Generator must run in this order:

1. Load canon locks
2. Load review protocol
3. Load Oracle presence constraints
4. Load depth and consent state
5. Collect location field
6. Derive environmental markers
7. Build environmental pressure profile
8. Build pre-date wound-trigger map
9. Store environmental field
10. Bring in birth date
11. Load scoring rules
12. Load modality sources independently
13. Generate time-anchor candidates when birth time is unknown, incomplete, guessed, or low-confidence
14. Apply environmental pressure to every anchor
15. Apply wound marker effects only as convergence-supported pressure
16. Route signals into portals
17. Run recursive extraction passes
18. Detect signal exhaustion
19. Rank strongest signals
20. Compile structured payload
21. Send final payload to Oracle render layer

If order changes, outputs drift.

---

## 5. NO QUESTIONNAIRE-FIRST RULE

The user does not begin with a personal-history questionnaire.

The system must not require childhood, family, trauma, relationship, self-description, or wound-description questions before the first read.

Lived experience may be added later as optional refinement.

Post-reading lived experience can refine:

- confidence
- intensity
- routing
- expression
- distortion
- suppression
- amplification
- section priority

It does not create the first read.

---

## 6. NO RAW INGREDIENT COOKING

Raw ingredients are never interpreted directly for the user.

Raw inputs must first become structured internal signals.

This includes:

- location field data
- environmental markers
- biome data
- abiotic data
- GeoPresence data
- birth data
- wound markers
- modality outputs
- portal activations
- relationship inputs
- Cadence tracking data
- optional lived-experience refinements

The user does not receive raw mechanics.

The user receives clear recognition, pattern visibility, and regulation guidance.

---

## 7. INDEPENDENT SOURCE RULE

Each source runs independently before synthesis.

Do not merge early.

Do not narrate early.

Do not force overlap.

Do not collapse one system into another.

Each modality, marker, pressure field, and portal signal must first produce its own structured extraction.

Only after independent extraction may signals be compared, weighted, routed, and ranked.

---

## 8. RECURSIVE EXTRACTION RULE

For each active environmental marker, wound marker, portal, domain, or modality signal:

1. Extract
2. Re-run against prior extraction
3. Add only new signal
4. Remove duplicates
5. Preserve the strongest prior signal
6. Continue until no meaningful new signal appears
7. Move to the next signal

The system decides when a thread is exhausted.

The user does not see this process.

---

## 9. SIGNAL EXHAUSTION RULE

A signal is considered exhausted when another pass produces no new:

- pattern
- mechanism
- trigger
- consequence
- relational impact
- body impact
- nervous-system signal
- regulation need
- routing destination
- confidence change

If no new signal appears, the Generator stops drilling that thread and routes forward.

---

## 10. ENVIRONMENT BEFORE MODULATION

Environmental field must be established before natal interpretation.

Do not apply birth-date interpretation, temporal anchors, biome modulation, GeoPresence modulation, wound marker effects, relational overlays, portal routing, or Cadence state before the environmental field exists.

Required sequence:

1. Establish environmental pressure field
2. Establish pre-date wound-trigger map
3. Introduce birth date
4. Generate temporal anchors when needed
5. Apply environmental pressure to anchor differences
6. Apply modality-specific extraction
7. Route into portals
8. Route into sections
9. Compile payload
10. Render through Oracle

---

## 11. TIME RECTIFICATION SUMMARY RULE

Time rectification summaries are not generic personality summaries.

They are contrast summaries.

They compare what changes across hidden candidate time anchors after the environmental field is active.

They compare:

- wound pressure
- attachment pressure
- rupture behavior
- shadow expression
- nervous-system response
- regulation pattern
- relationship behavior
- cost, consequence, trigger, and reset signatures

The user never chooses a clock time.

The user recognizes which summary fits.

Clock times remain hidden by default.

---

## 12. HIDDEN MECHANICS RULE

The user does not see:

- scoring math
- hidden time calibration
- raw environmental mechanics
- wound marker mechanics
- internal routing
- recursive pass logic
- portal traversal mechanics
- confidence calculations unless surfaced as a plain-language confidence band

Mechanics stay hidden by default.

The system may surface meaning.

The system must not expose machinery too early.

---

## 13. OUTPUT CONTRACT

Every compiled Generator payload must include:

- environmental field profile
- pre-date wound-trigger map
- pattern
- mechanism
- expression
- cost if unregulated
- impact on self
- impact on others
- body / nervous-system signal
- regulation requirement
- confidence band
- source signals
- portal routes
- section routes
- Oracle render instructions

No payload is complete without environmental field profile.

No payload is complete without both self-impact and other-impact.

No payload is complete without regulation requirement.

---

## 14. FAILURE RULE

If input is missing, uncertain, contradictory, or low-confidence:

- mark the confidence band
- degrade gracefully
- avoid hard claims
- do not hallucinate certainty
- do not fill gaps with prose
- do not invent convergence
- do not force a pattern

Low confidence must stay low confidence.

---

## 15. FINAL PAYLOAD RULE

The final Generator output is structured data.

The Oracle receives only:

- structured payload
- tone vector
- depth / consent state
- nesting chip options
- render sequence

The Oracle narrates only what the Generator has already found.

The Oracle may adjust pacing.

The Oracle may adjust delivery.

The Oracle may not change the findings.

---

The user does not need internal traversal language.

- recognition

- useful pattern visibility
- state awareness
- relationship awareness

It does not belong in normal user-facing narration.
