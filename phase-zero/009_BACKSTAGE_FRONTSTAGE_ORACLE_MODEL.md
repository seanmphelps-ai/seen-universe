# 009_BACKSTAGE_FRONTSTAGE_ORACLE_MODEL

This file defines the relationship between the generated chart payload and the live Oracle experience.

SEEN does not treat the first chart as the full experience.

The chart is the stored map.

The Oracle is the guided traversal of that map.

## Core Distinction

### Backstage

Backstage is the generated internal map.

It contains the structured source material the Oracle must route from.

Backstage may include:

- intake answers
- birth date
- birth place
- optional birth time
- childhood place
- lived places
- maternal environment
- family environment
- contextual pressure fields
- 6 AM / noon / 6 PM temporal calibration summaries
- selected resonance anchor
- working chart stack
- Western signals
- Vedic signals
- wound markers
- attachment indicators
- Jung inversion layer
- portal and lens routing
- dark chart pattern outputs
- sovereignty and protection routes
- suggested depth chips
- Cadence tracking fields

Backstage is not exposed all at once.

Backstage holds the living payload.

### Frontstage

Frontstage is what the user experiences.

Frontstage may include:

- the first chart summary
- Oracle conversation
- selected reveal sections
- nesting chips
- follow-up questions
- relational pattern explanations
- counter-pattern guidance
- sovereignty routes
- regulation paths
- printable/exportable selected sections
- Cadence prompts

Frontstage reveals from the map progressively.

## Primary Law

Every Oracle answer must trace back to the active generated map.

No Oracle answer should be generated only from the latest user message.

The latest user question selects a route.

The active map supplies the source signal.

The recursive pass protocol produces the final answer.

## Chart and Oracle Relationship

The chart gives the terrain.

The Oracle walks the user through the corridor they are standing in.

The chart can identify:

- the pattern
- the wound
- the relational cost
- the protection route
- the sovereignty path

The Oracle can deepen into:

- why this happens in arguments
- why this happens in intimacy
- why the user chases or freezes
- why another person withdraws, tests, projects, or withholds
- what childhood imprint may be active
- what Jung inversion may be operating
- what counter-pattern is required
- what boundary protects the center
- what should be tracked over time

The chart is finite.

The Oracle traversal can deepen because the user asks from inside a specific lived pattern.

## Temporal Calibration Flow

When exact birth time is unavailable or uncertain, SEEN may begin with three calibration summaries:

- 6 AM
- noon
- 6 PM

The user selects the summary that feels most recognizable.

The system then narrows recursively from the selected anchor.

The chosen summary becomes a working resonance anchor, not an absolute claim.

## Question-at-Any-Point Rule

The user may ask a question at any point.

The system must not abandon the active map when this happens.

The question should be treated as a route request into the existing map.

The Oracle must answer by combining:

- active map signal
- current user question
- selected lens
- relevant portal or domain
- recursive pass execution
- Oracle delivery rules

## Depth Chip Rule

Depth chips are route options generated from mapped signal.

They are not decorative prompts.

They should point toward available mapped depth, such as:

- argument pattern
- intimacy pattern
- attachment pattern
- Jung inversion
- childhood imprint
- wound marker expression
- environmental amplifier
- relational cost
- counter-pattern response
- sovereignty protection
- Cadence tracking

## Printout Rule

Printout is optional.

Printout should export selected map sections, not replace the Oracle traversal.

Possible exports:

- Dark Chart Summary
- Relationship Pattern Map
- Counter-Pattern Scripts
- Sovereignty Protection Plan
- Full Signature Report
- Cadence Tracking Summary

The app remains interactive by default.

The printable artifact is a selected snapshot from the living map.

## Final Lock

The chart is generated once as a living payload.

The Oracle reveals it progressively.

The user can ask from any point.

Every deeper answer must trace back to stored mapped signal.

No answer may drift away from the active map into improvisation.
